# Class 07 — MCP + RAG with Gemini Embeddings

## Goal (Roman Urdu)
Class 6 ke three Streamable HTTP MCP servers maintain hain: Travel (8001), Policy (8002), Work (8003). **Travel aur Work ki source files bilkul unchanged copy ki gayi hain.** Sirf Policy server mein keyword search ki jagah Gemini embedding 2 aur cosine similarity-based retrieval aaya hai.

## Architecture

```text
Policy .md → word chunking (85 words, 18 overlap) → Gemini embeddings
           → data/policy_index.json (local persistent vectors)
User question → Gemini query embedding → cosine score for every chunk
              → top-K source-labelled chunks → Policy MCP tool
Agent → MCPAdapter (Travel + Policy + Work) → Groq answer
```

## Step 1 — Review source policy
`data/company_policy.md` holds SAMPLE rules about economy class, hotels, expense reimbursement, approval, preparation. It is demo content only. Modify the file to learn how indexing changes. The document is loaded in `build_index.py`.

## Step 2 — How chunks work
`rag_utils.chunk_markdown` splits on words (85 words per chunk, overlap of 18). Overlap avoids abruptly cutting relevant context near boundaries. It is a teaching method, not sophisticated sentence/section-aware chunking. Every result gets `chunk_id`.

## Step 3 — Build Gemini embedding index BEFORE starting services

```powershell
python build_index.py
```

This calls `GoogleGenerativeAIEmbeddings(model="gemini-embedding-2")` and embeds document chunks **once during indexing**. It writes `data/policy_index.json` with vector arrays and `source_sha256` to detect document changes. Never manually edit vector content. Re-run indexing after policy edits or model changes.

## Step 4 — Run 3 servers
If Class 6 server is already running on ports 8001/8002/8003, stop it first. From `class_07`:

Terminal 1:
```powershell
python servers/travel_server.py
```
Terminal 2:
```powershell
python servers/policy_server.py
```
Terminal 3:
```powershell

```
Alternative one launcher: `python start_servers.py` (leave terminal open). HTTP MCP endpoints end in `/mcp`.

## Step 5 — Test Policy RAG directly (no Groq)

In a fourth terminal:

```powershell
python test_rag.py
```

You'll see questions about flight class, hotel policy and receipts followed by **ranked** source passages with `chunk_id`, `source` and cosine `score`. Scores are ranking signals and are **NOT confidence percentages**. If Gemini key or internet fails, tool returns a structured error rather than pretending to retrieve policies.

Also test all connections:

```powershell
python test_connections.py
```

Expected tool names per server: Travel has `search_flights`, `calculate_budget`, `get_live_weather`; Policy has `search_company_policy`; Work has `create_trip_task`, `list_trip_tasks`.

## Step 6 — Run Groq multi-MCP agent

```powershell
python agent.py
```

LangChain `MCPAdapter` registers server-prefixed tool names such as `travel_get_live_weather`, `policy_search_company_policy`, `work_create_trip_task`. Agent uses RAG to find policy passages; flight data and task creation are DEMO, weather comes from real Open-Meteo API. Agent tool choice/order depends on the model. Always inspect the printed message flow.

## Important code meanings

- `embed_documents(chunks)`: vector banata hai aur local index mein save karta hai.
- `embed_query(question)`: user query ko **same** model se vector banata hai.
- `cosine(query_vector, chunk_vector)`: semantic similarity score.
- `sorted(..., reverse=True)[:top_k]`: nearest chunks retrieve karta hai.
- `@server.tool()`: policy retrieval MCP client ke liye exposed hota hai.
- `asyncio.to_thread()`: blocking Gemini SDK call async server event loop ke bahar chalti hai.
- `policy://travel-summary`: fixed source content ab bhi available hai.
- `source_sha256`: document change par stale index detect karta hai.

## Error handling / troubleshooting

| Issue | Fix |
|---|---|
| `Index missing` | `python build_index.py` run karo. |
| `Policy changed` | Document edit ke baad index rebuild karo. |
| `GOOGLE_API_KEY is missing` | `.env` check karo; variable exact case. |
| `Connection refused` | Policy server start karo aur port 8002 verify karo. |
| `Address already in use` | Class 6 servers stop karo. |
| `429` / quota issue | Gemini account quota/billing check karo; repeated automatic retry mat karo. |
| `GROQ_API_KEY missing` | Groq key `.env` mein add karo. |
| Poor retrieval | Source text, chunk size, top_k aur task-specific query improve karo. |

## Practice

2. `chunk_words=60`, `overlap=12` ke sath index rebuild karo, compare results.
3. `top_k=1` aur `top_k=3` ke results compare karo.
4. Try paraphrased questions jahan exact keyword overlap kam ho.
5. Intentional document change karke stale-index error observe karo.

## Learning limitations
- Index is JSON + exhaustive cosine scan, suitable for small class datasets only.
- Does not implement tenant isolation, ACLs, relevance threshold evaluation, reranking, vector DB, or source-level access control.
- `Company policy` file is an illustrative local sample, not authenticated HR documentation.
- Business rules about flight/hotel are not booking permissions.
